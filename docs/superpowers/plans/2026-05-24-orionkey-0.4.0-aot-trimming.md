# OrionKey 0.4.0 — Native AOT & Trimming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make OrionKey safe and friction-free in `PublishAot` and `PublishTrimmed` deployments by marking the runtime projects AOT-compatible, defensively annotating the generated `TypeConverter` companion, shipping a real AOT sample app that round-trips every ID strategy plus Dapper + SQLite, and wiring an AOT publish + run step into CI.

**Architecture:** Two-flag strategy — `<IsAotCompatible>true</IsAotCompatible>` on each runtime project (`Moongazing.OrionKey`, `Moongazing.OrionKey.Testing`) turns on the trim/AOT analyzers and fails the build on any IL2026/IL3050/IL2104/IL3053 warning under the existing `TreatWarningsAsErrors`. A new self-contained `sample/Moongazing.OrionKey.AotSample` project (single-target `net10.0`, `PublishAot=true`) declares every ID strategy and round-trips each through `System.Text.Json` (via a source-generated `JsonSerializerContext`), `IParsable.Parse`, and Dapper + in-memory SQLite. The published native binary exits 0 on success; CI's new `aot-publish` matrix job builds and runs it on `ubuntu-latest`/`linux-x64` and `windows-latest`/`win-x64`. No new public runtime API.

**Tech Stack:** C# 13, .NET 8/9/10 multi-target (runtime), .NET 10 (AOT sample), Roslyn incremental source generator (netstandard2.0), `Dapper` 2.1.35, `Microsoft.Data.Sqlite` 9.0.0, GitHub Actions.

## Background for the implementer

OrionKey 0.3.1 ships as a NuGet package (`OrionKey`) plus a Testing helper (`OrionKey.Testing`). Both target `net8.0;net9.0;net10.0` (multi-target via the root `Directory.Build.props`) and run under `TreatWarningsAsErrors=true` with `AnalysisLevel=latest-recommended`. The source generator emits per-id companions: `<Name>JsonConverter` (file-scoped class + `[JsonConverter]` attribute), `<Name>TypeConverter` (file-scoped class + `[TypeConverter]` attribute), `<Name>ValueConverter` (EF Core, conditional), plus IParsable/ISpanParsable, IComparable, IEquatable, and Phase B integration converters (Dapper, Newtonsoft, MongoDB, Swashbuckle).

**Key facts for the AOT story:**

- Runtime code already avoids reflection: factories use `RandomNumberGenerator`/`Span<byte>`, the `OrionKey` facade uses `lock`+statics, `OrionKeyDiagnostics` uses `Trace.TraceWarning` + `System.Diagnostics.Metrics.Meter`/`Counter` (all AOT-safe in net8+), `WorkerIdResolver` uses `Environment.MachineName`.
- Generated `[TypeConverter(typeof(<Name>TypeConverter))]` on the struct uses `TypeConverterAttribute(Type)`, whose `Type` parameter is annotated with `[DynamicallyAccessedMembers(PublicParameterlessConstructor)]` since net8 — so the trimmer keeps the converter's ctor automatically. We still emit `[DynamicDependency]` defensively in Task 2 to make intent explicit and survive any future trimmer regression.
- Generated `[JsonConverter(typeof(<Name>JsonConverter))]` is handled by the S.T.Json source generator when the consumer registers a `JsonSerializerContext` covering the id type. The AOT sample uses that pattern explicitly.
- EF Core 9+ has its own AOT/trim annotations; OrionKey's emitted `ValueConverter` is reachable through the EF entity model, no extra annotation needed.
- **Out of AOT scope (per spec):** Newtonsoft.Json, MongoDB.Driver, Swashbuckle.AspNetCore — these libraries are not AOT-clean as of mid-2026. The AOT sample deliberately does NOT exercise their emitters. Their Phase B emitters continue to ship and work in non-AOT scenarios.
- Test projects (`*.Tests`) set `<IsPackable>false</IsPackable>` and target only `net10.0`. They do NOT get `IsAotCompatible=true` — tests are never published AOT and pulling Newtonsoft/Mongo/Swashbuckle into AOT mode would explode warnings.

**Current version state:** `Directory.Build.props` `<Version>` is `0.3.1`. `OrionKeyDiagnostics.cs` meter version string is still `"0.3.0"` — drift introduced by PR #2 (logo refresh) which forgot to bump it. Phase C's version bump corrects both to `0.4.0`.

## Task 2: Defensive `[DynamicDependency]` on TypeConverter companion

**Files:**
- Modify: `src/Moongazing.OrionKey.Generators/Emit/TypeConverterEmitter.cs`
- Modify: `tests/Moongazing.OrionKey.Generators.Tests/TypeConverterTests.cs`

`TypeConverterAttribute(Type)` in .NET 8+ already annotates its `Type` parameter with `[DynamicallyAccessedMembers(PublicParameterlessConstructor)]`, so the trimmer should keep the converter's ctor automatically. Adding a `[DynamicDependency]` next to the `[TypeConverter]` attribute on the struct is defensive: it documents intent and protects against future trimmer regressions or older-runtime edge cases. The cost is one extra attribute per generated id; the benefit is explicit guarantee that the generated `<Name>TypeConverter`'s public constructors survive trimming.

```csharp
    {

        Assert.Contains(
            "global::System.Diagnostics.CodeAnalysis.DynamicDependency",
            output);
        Assert.Contains(
            "DynamicallyAccessedMemberTypes.PublicConstructors",
            output);
        Assert.Contains(
            "typeof(OrderIdTypeConverter)",
            output);
```

```csharp
failures += RoundTripJson(SessionId.New(), stjOptions);
failures += RoundTripJson(AccountId.New(), stjOptions);

failures += RoundTripJson(DocumentId.New(), stjOptions);

failures += RoundTripParse(UserId.New(), s => UserId.Parse(s, null));
failures += RoundTripParse(TenantId.New(), s => TenantId.Parse(s, null));
failures += RoundTripParse(InvoiceId.New(), s => InvoiceId.Parse(s, null));

return failures;

static int RoundTripJson<T>(T id, JsonSerializerOptions options) where T : IEquatable<T>
{
    var json = JsonSerializer.Serialize(id, options);
    var restored = JsonSerializer.Deserialize<T>(json, options);
    if (restored is null || !id.Equals(restored))
    {
        Console.Error.WriteLine($"JSON round-trip failed for {typeof(T).Name}: {id} -> {json} -> {restored}");
        return 1;
    }
    Console.WriteLine($"  STJ  {typeof(T).Name,-11} {id}");
    return 0;
}

static int RoundTripParse<T>(T id, Func<string, T> parse) where T : IEquatable<T>
{
    var text = id.ToString() ?? string.Empty;
    var restored = parse(text);
    if (!id.Equals(restored))
    {
        Console.Error.WriteLine($"Parse round-trip failed for {typeof(T).Name}: {id} -> {text} -> {restored}");
        return 1;
    }
    Console.WriteLine($"  Parse {typeof(T).Name,-11} {id}");
    return 0;
}
```

In `.github/workflows/ci-cd.yml`, immediately after the closing of the `build-and-test:` job (and before `publish:`), insert this new job:

```yaml
  aot-publish:
    needs: build-and-test
    strategy:
      fail-fast: false
      matrix:
        include:
          - os: ubuntu-latest
            rid: linux-x64
            binary: Moongazing.OrionKey.AotSample
          - os: windows-latest
            rid: win-x64
            binary: Moongazing.OrionKey.AotSample.exe
    runs-on: ${{ matrix.os }}

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup .NET 10
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'

      - name: Restore
        run: dotnet restore ${{ env.SOLUTION_PATH }}

      - name: Publish AOT sample
        run: dotnet publish sample/Moongazing.OrionKey.AotSample/Moongazing.OrionKey.AotSample.csproj -c Release -r ${{ matrix.rid }} --self-contained --no-restore

      - name: Run AOT sample (Linux)
        if: matrix.os == 'ubuntu-latest'
        run: ./sample/Moongazing.OrionKey.AotSample/bin/Release/net10.0/${{ matrix.rid }}/publish/${{ matrix.binary }}

      - name: Run AOT sample (Windows)
        if: matrix.os == 'windows-latest'
        run: .\sample\Moongazing.OrionKey.AotSample\bin\Release\net10.0\${{ matrix.rid }}\publish\${{ matrix.binary }}
```

(Indentation: the new job sits at the same indent level as `build-and-test` and `publish` — typically two spaces inside the `jobs:` key.)
